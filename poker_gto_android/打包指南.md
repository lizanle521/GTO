# APK 打包指南

## 先看这个结论

**Buildozer 只能在 Linux 上运行，Windows 原生不支持。** 这不是配置问题，是工具本身的限制——它依赖大量 Linux 专有的编译工具链（autoconf、libtool、NDK 交叉编译等）。

所以打包路径只有三种，按推荐度排序：

| 方案 | 难度 | 耗时 | 适合 |
|---|---|---|---|
| **① GitHub Actions 云端** | ⭐ 最容易 | 20-40 分钟 | **推荐所有人**，不用装任何环境 |
| **② WSL2 本地** | ⭐⭐ 中等 | 首次 40-80 分钟 | 需要频繁改代码反复打包 |
| **③ Linux 机器/虚拟机** | ⭐⭐⭐ 较难 | 首次 40-80 分钟 | 有现成 Linux 环境 |

---

## 方案 ①：GitHub Actions 云端打包（推荐）

**为什么推荐**：不用在本机装 Java、Android SDK、NDK（合计 3-5 GB），不用折腾 WSL。推到 GitHub 就不用管了，打包完直接下载 apk。

### 步骤

**1. 建一个 GitHub 仓库**

到 https://github.com/new 新建一个仓库，比如叫 `gto-helper`，选 Private 或 Public 都行。

**2. 把项目推上去**

仓库里已经有现成的 workflow 文件（`.github/workflows/build-apk.yml`），直接推：

```bash
cd C:\Users\admin\WorkBuddy\2026-09-12-21-30-49

git init
git add .
git commit -m "GTO 助手：安卓版首版"
git branch -M main
git remote add origin https://github.com/你的用户名/gto-helper.git
git push -u origin main
```

> 如果这台机器上没有 git，先装一个：https://git-scm.com/download/win

**3. 等待自动构建**

推送后，打开仓库页面的 **Actions** 标签，会看到 "Build Android APK" 任务自动开始跑。点进去能看实时日志。

**4. 下载 apk**

构建成功后（约 20-40 分钟），在该次运行的页面**底部**找到 **Artifacts** 区域，点 `gto-helper-apk` 下载。解压后就是 apk。

### 手动触发

改完代码想重新打包，不用非得提交代码。到 Actions 页面 → 选左侧 "Build Android APK" → 右侧 **Run workflow** 按钮 → 点绿色按钮即可。

### 免费额度

GitHub 免费账号每月有 2000 分钟 Actions 额度（私有仓库）。公开仓库**完全不限时长**。一次打包约 20-40 分钟，够用。

### 常见问题

**首次构建特别慢**：正常。要下载 Android SDK + NDK（3-5 GB）。workflow 里配了缓存，第二次构建会快很多（约 10-15 分钟）。

**提示 `if-no-files-found: error`**：说明 apk 没生成，构建在某一步失败了。查错顺序：

1. 点进那次失败的运行，先看页面**顶部的 Summary**（标题 "构建失败诊断"）——
   workflow 会把匹配到的错误行和日志尾部直接贴在那里，多数情况一眼就能看出原因。
2. 还不够就下载页面底部的 **Artifacts → `build-log`**，那是完整的构建日志。
   失败时它也会上传，不用重新跑一遍去复现。

**云端构建最常见的失败原因：SDK 许可证没被接受。** 报错形如：

```text
Failed to install the following Android SDK packages as some licences have not been accepted
```

原因是 `buildozer.spec` 里 `android.accept_sdk_license` 的**默认值是 `False`**，
此时 buildozer 会以交互方式询问是否接受许可证；GitHub Actions 上没有终端可以输入，
SDK 组件就装不上，构建在下载 SDK 那一步就挂了。

项目里已经设成 `True`：

```ini
android.accept_sdk_license = True
```

**这一行不要删。** 本地手动打包时删掉也无妨（会弹提示让你确认），但云端必须是 `True`。

**想改应用名或包名**：编辑 `poker_gto_android/buildozer.spec` 的 `title` 和 `package.name`、`package.domain`。

## 方案 ②：WSL2 本地打包

### 前置：装 WSL2

以**管理员身份**打开 PowerShell：

```powershell
wsl --install -d Ubuntu
```

装完重启电脑，Ubuntu 会提示你设置用户名密码。

> ⚠️ 如果提示"此程序被组策略阻止"，说明 WSL 被系统策略或安全软件禁用了。那就走方案 ①，或者找 IT 解除限制。

### 装依赖并打包

打开 Ubuntu 终端：

```bash
# 1. 更新包列表
sudo apt update

# 2. 装编译依赖
sudo apt install -y git zip unzip openjdk-17-jdk \
    autoconf libtool pkg-config \
    zlib1g-dev libncurses5-dev libncursesw5-dev libtinfo5 \
    cmake libffi-dev libssl-dev python3-pip

# 3. 装 Buildozer
pip3 install --user buildozer cython==0.29.36
export PATH="$HOME/.local/bin:$PATH"

# 4. 进项目目录（WSL 里访问 Windows 盘是 /mnt/c/...）
cd /mnt/c/Users/admin/WorkBuddy/2026-09-12-21-30-49/poker_gto_android

# 5. 一键打包（脚本会自己检查环境）
chmod +x build_apk.sh
./build_apk.sh
```

或者手动执行：

```bash
python3 preflight.py        # 先体检
buildozer android debug     # 再打包
```

打包结果在 `bin/` 目录下。

### 加速技巧

**把项目拷到 WSL 内部**：在 `/mnt/c/` 下编译会慢很多（跨文件系统）。建议：

```bash
cp -r /mnt/c/Users/admin/WorkBuddy/2026-09-12-21-30-49/poker_gto_android ~/gto
cd ~/gto
./build_apk.sh
```

**用国内 pip 源**：

```bash
pip3 install --user -i https://pypi.tuna.tsinghua.edu.cn/simple buildozer cython==0.29.36
```

### 常见报错

**`UnicodeDecodeError` 或中文乱码**：在 `buildozer.spec` 里 `log_level = 2` 已知在某些终端会有编码问题，改成 1 试试。

**`Failed to install the following Android SDK packages as some licences have not been accepted`**
（或构建卡在 "Accept? (y/N)" 不动）：`android.accept_sdk_license` 没开。
`buildozer.spec` 里加上 `android.accept_sdk_license = True`。
命令行交互式打包时可以临时用 `yes | buildozer -v android debug` 代替。

**`ImportError: No module named 'Cython'`**：Cython 版本太新。锁定 `cython==0.29.36`。

**卡在 "Downloading NDK"**：NDK 有 1 GB 多，网络慢时很煎熬。可以手动下载后放到 `~/.buildozer/android/platform/` 下。

**`SDK manager not found`**：删掉 `~/.buildozer` 重来一次，让 Buildozer 重新初始化。这个目录有 3-5 GB，清理前留意。

## 打包前必做：体检

项目里带了个体检脚本，能在打包前把坑查出来，省得等 40 分钟才发现问题：

```bash
python3 preflight.py
```

它会检查：

- 必需源文件是否齐全
- 中文字体是否存在、格式是否对、有没有版权问题
- `buildozer.spec` 配置是否正确（requirements 有没有误写 kivy、权限够不够、字体有没有被打包）
- 所有 Python 文件语法是否正确
- 当前系统能不能打包
- 磁盘空间够不够

任何一项 FAIL 都建议先解决再打包。

## 装到手机上

**方式一：直接传文件**

把 apk 通过微信/QQ/数据线传到手机，点击安装。安卓会提示"未知来源"，需要在设置里允许一下。

**方式二：adb 安装**

```bash
adb install -r bin/gtohelper-0.1.0-debug.apk
```

**注意**：`debug` 版 apk 是调试签名，可以正常安装使用，但不能上架应用商店。要上架需要 `buildozer android release` 并配置正式签名（需要自己生成 keystore）。

## 首次运行会看到什么

1. 启动需要 3-8 秒（Python 运行时解压，属正常现象，原生的会快很多）
2. 界面是三个页签：**实时识别 / 训练 / 设置**
3. **先去「设置」页填 API Key**，否则摄像头识别用不了
4. **训练功能不需要 Key**，完全不联网也能刷题

### 关于 API Key

默认预设是**智谱 GLM（`glm-4v-flash`，免费）**。到 https://open.bigmodel.cn 注册，在控制台创建 API Key 填进去即可。

Key 只存在手机本地（App 私有目录），不会上传到任何地方。

## 打包后的 apk 有多大

Python + Kivy 打包的 apk 大概 **45-65 MB**（含 Python 解释器、Kivy、numpy、字体）。比原生 App 大，这是这种方案的固有代价。

如果在意体积，可以：

- 在 `buildozer.spec` 里把 `android.archs` 只留 `arm64-v8a`（现在留了两种架构，砍一半能省不少）
- 换更小的中文字体子集（只保留常用汉字）

## 出问题怎么排查

**看详细日志**：

```bash
buildozer -v android debug 2>&1 | tee build.log
```

`-v` 是 verbose，信息量很大但有用。日志太长可以搜 `Error`、`Command failed`、`Traceback`。

**手机上看运行日志**：

```bash
adb logcat | grep python
```

能过滤出 Python 层的错误，排查闪退很有用。

**清缓存重来**：

```bash
rm -rf .buildozer
buildozer android clean
buildozer android debug
```

`.buildozer` 目录里是解压后的 p4a 和构建中间产物，有 3-5 GB。
