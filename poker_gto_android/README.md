# GTO 助手（安卓 App）

一个**德州扑克 GTO 学习工具**，安卓端。摄像头拍下牌面 → AI 识别 → 给出基于 GTO 范围表的行动建议；同时内置刷题训练模式。

> **用途声明**：本工具面向**学习与训练**。请勿用于真实牌局的实时决策——在正规赛事中使用实时辅助（RTA）属作弊行为，会被禁赛。识别结果仅供参考，实际决策请自行判断。

---

## 一、这个 App 能做什么

| 功能 | 说明 | 是否需要联网 |
|---|---|---|
| **实时牌面识别** | 摄像头对着牌桌，自动抽帧识别手牌/公共牌/位置 | 需要（调 AI 接口） |
| **GTO 行动推荐** | 识别后给出翻前开池/弃牌、翻后下注建议 | **不需要**（本地计算） |
| **刷题训练** | 三个模块出题：翻前开池、翻前对抗加注、翻后决策 | 不需要 |
| **成绩统计** | 正确率、分模块正确率、历史记录 | 不需要 |

**关键设计**：GTO 推荐逻辑全部基于**内置的翻前范围表**，完全离线、免费、无 API 消耗。AI 只负责把牌"读"进来，读错可以手动改。所以即使你没有 API Key，训练功能也完全可用。

## 三、先在电脑上跑起来（调试）

安卓打包耗时较长，建议先在 Windows 上验证功能。

### 1. 安装依赖

双击 **`install.bat`** 即可。它会自动装好 Kivy、Pillow、numpy 并验证导入。

手动执行等价命令：

```bat
C://Users//admin//.workbuddy//binaries//python//envs//default//Scripts//python.exe -m pip install "kivy==2.3.1" "pillow>=10,<11" numpy
```

> **关于 Pillow 版本**：Kivy 2.3.1 在其 `base` extra 里声明了 `pillow<11`，
> 所以 Pillow 会被装成 10.x。这是正常的，不是装错了——本项目只用 Pillow
> 做 JPEG 编码和图像缩放，10.x 完全够用。**不要手动升级 Pillow 到 11+**，
> 那会破坏 Kivy 的依赖一致性。

### 2. 启动

双击 **`start_debug.bat`**。会弹出一个窗口，界面和手机上基本一致。

> 这两个 `.bat` 文件都是**纯 ASCII + CRLF** 格式。Windows 的 cmd.exe 默认按
> GBK 读批处理文件，如果改回 UTF-8 中文内容或 LF 换行，脚本会立刻报一堆
> `'xxx' 不是内部或外部命令` 的碎片错误。修改时请保持编码不变。

### 3. 跑测试（可选）

```bat
cd poker_gto_android
set PYTHONPATH=.
C://Users//admin//.workbuddy//binaries//python//envs//default//Scripts//python.exe test_postflop.py
C://Users//admin//.workbuddy//binaries//python//envs//default//Scripts//python.exe test_app.py
```

两套测试覆盖听牌识别、超对识别、建议生成、界面构建、答题流程、设置读写、500 组随机牌一致性。

## 五、打包成安卓 apk

### ⚠️ 重要限制

**Buildozer 只能在 Linux 或 macOS 上运行，Windows 原生不支持。**

Windows 用户有三条路：

| 方案 | 难度 | 说明 |
|---|---|---|
| **GitHub Actions 云端** | 容易 | 推到 GitHub 自动打包，不用装任何环境，**推荐** |
| **WSL2** | 中 | 在 Windows 里装 Linux 子系统 |
| **Linux 机器/虚拟机** | 高 | 需要自己准备环境 |

**→ 完整步骤见 [打包指南.md](打包指南.md)**，三条路径的详细命令、加速技巧、排错方法都写在里面。

### 打包前先体检

```bash
python3 preflight.py
```

会检查源文件完整性、中文字体格式与版权、`buildozer.spec` 配置、代码语法、系统环境、磁盘空间。有问题会明确指出哪里要改，省得等 40 分钟才发现。

### 关于中文字体

Kivy 默认字体不含中文，不处理的话界面全是方块。项目里 `assets/chinese.ttf` **已经放好了开源字体 Noto Sans SC**（SIL OFL 1.1，可商用，10 MB），直接打包即可。

想换字体：

```bash
python pack_font.py --force    # 重新下载开源字体
python pack_font.py --system   # 用系统字体（仅本机调试，勿发布）
```

> ⚠️ 别把 Windows 自带的微软雅黑、宋体打进要分发的 apk——那些是商业字体，有侵权风险。

## 六、技术实现要点

### 实时识别的成本控制

摄像头不能每帧都送 AI（费用爆炸、也没必要）。`realtime.py` 做了两层过滤：

1. **变化检测**：把画面降采样成 32×32 灰度图，与上一帧做差分。变化率低于阈值（默认 8%）说明画面没变，直接跳过。
   - 这里阈值调得很低，因为**发牌只改变画面 5%-15% 的区域**，阈值太糙会漏掉。
2. **节流**：两次识别之间至少间隔 `capture_interval` 秒（默认 3 秒）。

只有"画面确实变了" **且** "距上次识别够久了"，才真正调用 AI。识别统计在实时识别页底部实时显示。

### 翻后决策的判断顺序

`postflop_advice()` 的顺序很关键，写错会导致建议和牌力不符：

1. **顺子及以上** → 下大注（约 3/4 池）
2. **两对/三条/葫芦/四条** → 下大注建池
3. **超对** → 下注（注意：超对是**成牌**，不是听牌）
4. **强听牌**（同花听牌 或 两头顺）→ 半诈唬
5. **弱听牌**（卡顺）→ 小注或过牌
6. **顶对** → 按牌面高低决定下注尺度
7. **弱牌** → 过牌

### 听牌识别逻辑

区分**两头顺**和**卡顺**的方法：数补牌点的个数。

- **AK 在 QJ2**：只有 T 能补（TJQKA）→ 1 个补牌点 → **卡顺**（4 张出路）
- **98 在 T72**：补 J 成 789TJ、补 6 成 6789T → 2 个补牌点 → **两头顺**（8 张出路）

注意不能用"缺口是否在窗口两端"来判断——AKQJ 缺 T，T 在窗口端点，但它只能成一条顺子，是卡顺。

### 范围表的一致性

`ranges.py` 用紧凑写法定义范围（`"A5s-A2s"`、`"77+"`、`"KTs+:0.5"`），加载时自动展开并**校验**：同一手牌在 3bet 范围和跟注范围内的权重之和不能超过 100%。

如果数据写冲突了，`reconcile_ranges()` 会自动从跟注范围里扣掉 3bet 已占的权重，从根本上杜绝"同一手牌既 100% 3bet 又 100% 跟注"这种矛盾。

## 七、已知限制

1. **打包限制**：Buildozer 不支持 Windows，必须走 WSL2 / 云构建 / Linux。
2. **apk 体积**：Python 打包的 apk 约 40-60 MB（含 Python 解释器和 Kivy），比原生 App 大不少。
3. **启动速度**：首次启动需要几秒（解压 Python 运行时），比原生慢。
4. **摄像头**：Kivy 的 `Camera` 在部分安卓机型上兼容性一般，可能出现预览比例不对或启动慢。识别是"拍一帧送去分析"，不是连续视频流分析。
5. **识别准确率**：牌面识别受光线、角度、遮挡影响，可能出错。**所有识别结果都要人工校对**——GTO 推荐对牌面错误零容忍，牌读错一步，建议就全错。
6. **后台保活**：安卓会杀后台进程，切出去再回来可能需要重新开摄像头。
