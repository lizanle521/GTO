## 安卓 App：GTO 助手（poker_gto_android）

**需求演变**：桌面识别软件 → 实时视频流识别 app → **明确为安卓 app**（平台纠偏：之前用 PyQt6 做桌面版，无法上安卓，改用 Kivy）。

**项目结构**（`poker_gto_android/`）：
- `poker_core.py` — 牌型评估（7 选 5，分值编码 `类别*15^5+...`）、起手牌强度排序
- `ranges.py` — 翻前 GTO 范围表，紧凑写法（`A5s-A2s`/`77+`/`KTs+:0.5`），`reconcile_ranges()` 加载时自动削平 3bet 与 call 的权重冲突

- `recognizer.py` — 多模态识别，OpenAI 兼容协议，7 个服务商预设，默认 `glm-4v-flash`（免费）

- `pack_font.py` — 把中文字体复制到 `assets/chinese.ttf` 随包分发

- `test_postflop.py` / `test_app.py` — 测试，**当前全部通过**

3. **`test_app.py` 顺子测试用例本身写错**：`9h8h` + `Ts7d2c` 只有 4 张顺畅，不成顺。改成 `JhTh` + `9s8d7c`（真成顺），并把原案例改为验证「两头顺听牌」。

**环境注意**：

## 修复 install.bat 报错（编码问题 + 环境损坏）

**用户反馈**：「install.bat 跑不起来，报错」。

**根因 1 —— .bat 编码不匹配（根本原因）**：
我用 Write 工具写出的 `.bat` 是 **UTF-8 + LF**，而 Windows `cmd.exe` 在中文系统上
按 **GBK** 读批处理文件。UTF-8 中文字节被当 GBK 解释成乱码，乱码里又混入引号/空格，
把命令**从中间劈开**，于是报错全是 `'n.exe'`、`'rade'`、`'HON" -c "import'`、
`'per'`、`'elopment'` 这类碎片。
- 修法：`.bat` 必须满足三条 —— **纯 ASCII**（一个中文都不能有）、**CRLF 换行**、
  **无 BOM**。注意即使内容全改英文，只要换行还是 LF，cmd.exe 仍会读错行。
- 已把 `install.bat` 内容全改英文，并用 Python 以二进制方式写出，
  强制 `encode("ascii")` + `\n` → `\r\n`。
- 同时把 `启动调试.bat` 改名为 **`start_debug.bat`**（ASCII 文件名，避免引用时再踩编码坑），
  删除旧文件，并全仓库统一更新引用。

**根因 2 —— Pillow 版本反复横跳**：
排查中发现 pip 每次运行都在 Pillow 12.x 与 10.x 之间来回装卸。查 Kivy 元数据
（`Kivy-2.3.1.dist-info/METADATA`）得到答案：
```
Requires-Dist: pillow<11,>=9.5.0; extra == "base"
```
**Kivy 2.3.1 的 `base` extra 明确要求 `pillow<11`**。之前我把 Pillow 手动升到 12.3.0
是错的，会破坏依赖一致性。
- 修法：`install.bat` 里显式写 `"kivy==2.3.1" "pillow>=10,<11" numpy`，
  让约束明确、不再来回折腾。Pillow 10.x 对本项目完全够用（只做 JPEG 编码与缩放），
  已用 `Image.save/resize` 实测通过。
- 另外发现 `kivy[base,media]` 里的 media extras 会拉 `kivy-deps.gstreamer`（141 MB），
  本项目不播音视频，已改为裸 `kivy==2.3.1`。

**根因 3（附带损失，已修复）——环境被我自己搞坏**：
排查过程中我跑 pip uninstall 时进程被 SIGTERM 强杀（超时），导致：
- `kivy/` 包目录消失，只剩 `Kivy-2.3.1.dist-info` 元数据 → pip 误报「已安装」
  但 `import kivy` 报 `ModuleNotFoundError`
- 残留 `~ivy_deps.gstreamer-0.3.4.dist-info` 损坏目录（pip 一直刷 WARNING）
- `numpy` 目录残缺（只有 12 个条目，`version` 子模块丢失）→ 报误导性的
  `ImportError: cannot import name 'version' ... circular import`
- 修法：手动删除损坏残留，`pip install --force-reinstall numpy`，重装 `kivy==2.3.1`。
  当前环境：Kivy 2.3.1 / Pillow 10.4.0 / numpy 2.5.3，全部导入正常。

**教训**：在 Windows 上跑长时间 pip 操作时，不要设太短的 timeout ——
被强杀会留下半装的包，比跑得久麻烦得多。

**preflight.py 增强**：新增【4b】批处理文件编码检查，自动检测 `.bat` 是否
「纯 ASCII + CRLF + 无 BOM」，把这类问题在打包前暴露，不用靠人肉踩坑。

**最终验证**：7 模块自检 + 2 套单元测试 + 11 文件语法编译 + 2 个 .bat 编码检查
全部通过；`install.bat` 实测 `returncode=0`、碎片报错 **0 条**；
preflight 10 项通过 / 2 警告 / 1 失败（仅 Windows 不能打包，预期内）。
